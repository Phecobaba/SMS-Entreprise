# Teacher Results — Subject/class pair

Status: **New design reference.** HTML: `../screens/teacher-results-pair.html`.

## Scope and contents
Breadcrumb to **My classes and subjects**. The header repeats the exact pair label and current Term. Show pupils in **all arms** of that assigned class, with pupil name, arm, registration number (where issued), score status and **Enter scores / Continue scores / View scores** action. Display Not started, Draft, Submitted and Approved distinctly. Filter by arm or search name/registration number *within this pair only*. The all-pupils Students list must not appear here. Rows navigate to score entry only for this pair, pupil and Term.

## CSV workflow (design proposal requiring backend verification)
Use **Download roster template** generated by the server for the authenticated pair and Term. Columns: `registration_number`, `student_name` (reference only), then one score column per actual configured assessment component. No raw `student_id`, `subject_id`, `term_id`, or `component_id` columns for the Teacher to enter. The server should resolve each row by **unique, current registration number in the school**, check that the pupil is active and belongs to this pair, and validate the component names/maxima from the configured template. Names are for human checking and must **not** be the identity key. If any pupil in the pair lacks a usable registration number, block this simplified CSV path with a clear explanation and keep individual entry available; do not silently fall back to names.

Require a preview of parsed rows and errors before apply; reject unknown, duplicate, missing, cross-pair, wrong-Term, stale or approved/locked rows. Preserve existing result status/approval restrictions and import transaction behavior. **Backend Agent must confirm** current CSV service and safe roster-number resolution before Codex implements this proposed format. Do not claim it already exists. A teacher can only upload for a pair they are assigned to.

## Empty and responsive
No pupils in assigned class: show **No pupils in this class yet**; no upload. Desktop table; at 390px use stacked row cards with accessible labels and 44px+ row actions, not horizontal page scrolling. The HTML sample's CSV buttons are non-persistent design controls.
